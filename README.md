# Beraum — Архитектура витрины и интеграция с маркетплейсами

Система не является классическим e-commerce;
Основной флоу — генерация лидов, обработка B2B-заявок, сервисное обслуживание и навигация трафика покупателей на маркетплейсы с актуализацией остатков FBO/FBS. Проект спроектирован с упором на отказоустойчивость, защиту данных и строгую типизацию.

## Технологический стек

- **Фреймворк:** Next.js 16 (App Router), React 19.
- **БД и ORM:** PostgreSQL 16, Drizzle ORM.
- **Инфраструктура:** Docker, MinIO (S3-хранилище), Caddy (Reverse Proxy/TLS).
- **Стилизация:** Tailwind CSS v4, shadcn/ui.
- **Безопасность и Валидация:** NextAuth.js v5, Zod, bcrypt-ts.
- **Интеграции:** Ozon API, Wildberries API.

## Архитектура и Security

Проект реализует парадигму Zero Trust и спроектирован с учетом следующих инженерных практик:

- **Изоляция слоев и валидация:** Мутации данных строго изолированы в Server Actions с обязательной Zod-валидацией DTO. Клиент не имеет доступа к критической бизнес-логике и секретам.
- **Безопасная загрузка медиа:** Загрузка файлов (чеков, фото неисправностей) клиентами реализована через кратковременные Presigned POST URL напрямую в MinIO (S3), исключая нагрузку на Node.js и предотвращая DoS/RCE векторы через файловую систему сервера.
- **Rate Limiting:** Защита API-роутов и форм (IP hashing + хранение стейта в PostgreSQL). Блокирует брутфорс и спам-заявки.
- **Синхронизация API:** Фоновые сервисы для синхронизации остатков и цен с обработкой Rate limits маркетплейсов, чанкированием запросов и изоляцией сбоев (одна упавшая страница не рушит транзакцию).
- **Colocation:** Локальные компоненты страниц хранятся в приватных директориях (`_components`), исключая утечку внутренней логики в публичный роутинг Next.js.

## Локальный запуск

Используйте строго `npm ci` для гарантии детерминированной сборки зависимостей. Установка через `npm install` может привести к конфликту версий.

```bash
# 1. Клонирование и базовая настройка
git clone <repo-url> && cd beraum-store
cp .env.example .env.local

# 2. Поднятие инфраструктуры (БД и объектное хранилище)
docker compose up -d postgres minio minio-init

# 3. Установка зависимостей
npm ci

# 4. Накатывание миграций и сидирование справочников
npm run db:migrate
npm run db:seed
npm run db:seed-admin

# 5. Запуск
npm run dev
```

## Продакшн развертывание (Аудит)

Сборка осуществляется через многоэтапный `Dockerfile` (режим `standalone`).

**Критические требования перед деплоем:**

1. Заменить все дефолтные пароли и токены в `.env.local` для локальной разработки и в '.env.production' для прод-среды (Postgres, MinIO, Auth Secret).
2. Настроить строгие CORS-политики для бакета `support-media` в MinIO, разрешив POST только с вашего домена.
3. Весь внешний трафик должен терминироваться на Caddy (см. `Caddyfile`) для принудительного HTTPS и внедрения security-заголовков (`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`). Прямой доступ к Node.js или интерфейсу MinIO извне недопустим.
